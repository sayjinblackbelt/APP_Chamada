# Requisitos do APP Chamada

## 1. Problema

Educadores precisam registrar rapidamente a presença dos educandos em diferentes oficinas e unidades. O processo deve ser simples o suficiente para ser usado durante a rotina da oficina, sem exigir conhecimento técnico.

## 2. Usuário principal

Educador, professor ou monitor responsável pela chamada.

## 3. Requisitos funcionais do MVP

### RF01 — Selecionar unidade
O usuário deve selecionar a unidade antes de iniciar a chamada.

### RF02 — Selecionar oficina/turma
Após escolher a unidade, o usuário deve visualizar somente as oficinas/turmas vinculadas àquela unidade.

### RF03 — Iniciar chamada
O usuário deve iniciar uma chamada para a data atual.

### RF04 — Visualizar educandos
O aplicativo deve apresentar a lista de educandos da oficina/turma selecionada.

### RF05 — Registrar presença
O usuário deve conseguir marcar um educando como presente com um toque.

### RF06 — Registrar ausência
O usuário deve conseguir marcar um educando como ausente com um toque.

### RF07 — Alterar registro
Antes de finalizar a chamada, o usuário deve poder alterar presente/ausente.

### RF08 — Finalizar chamada
O aplicativo deve permitir encerrar a chamada e apresentar um resumo.

### RF09 — Histórico
O usuário deve conseguir consultar chamadas já registradas.

## 4. Requisitos não funcionais

- Interface responsiva para celular e tablet Android.
- Botões grandes e legíveis.
- Poucas etapas para realizar a chamada.
- Operação com conexão instável; o MVP deve priorizar armazenamento local.
- Sem necessidade de recursos de IA para a função principal.
- Dados reais não devem ser incluídos no código ou no GitHub.

## 5. Fora do MVP

- Login complexo.
- Reconhecimento facial.
- Biometria.
- Notificações automáticas.
- Relatórios estatísticos avançados.
- Integração com sistemas externos.
- Inteligência artificial na chamada.

Esses itens podem ser avaliados posteriormente conforme a necessidade real.
