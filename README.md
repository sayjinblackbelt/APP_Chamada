# 📋 Attendance Management App

🇧🇷 Português | [🇺🇸 English](README.en.md) | [🇪🇸 Español](README.es.md)

> Aplicativo em desenvolvimento para tornar o registro de presença em oficinas, turmas e atividades educacionais mais simples, rápido e organizado.

## 📌 Origem do projeto

A ideia surgiu a partir de uma **demanda institucional real identificada em 2025**, relacionada à necessidade de melhorar e simplificar o processo de registro de frequência em atividades educacionais.

Em **2026**, o projeto passou da fase de necessidade identificada para o início do desenvolvimento técnico e da estruturação do MVP.

O objetivo é transformar uma demanda operacional real em uma solução digital prática e progressivamente evolutiva, sem vincular publicamente o projeto a uma instituição específica.

## 🎯 Objetivo

Substituir ou simplificar processos manuais de chamada, permitindo que educadores e equipes responsáveis registrem a frequência por celular ou tablet com poucos toques.

A solução busca reduzir:

- tempo gasto com registros manuais;
- retrabalho;
- inconsistências;
- dificuldade de consulta ao histórico.

## 📱 MVP

- Seleção da atividade, oficina ou turma;
- lista de participantes;
- registro de presente ou ausente;
- registro automático de data e horário;
- correção antes da confirmação;
- resumo de presentes e ausentes;
- histórico básico de chamadas.

## 🧭 Fluxo principal

```text
Selecionar atividade
        ↓
Selecionar turma
        ↓
Carregar participantes
        ↓
Registrar presença
        ↓
Revisar informações
        ↓
Confirmar chamada
        ↓
Salvar histórico
```

## 🧠 Princípios do projeto

1. **Simplicidade acima de excesso de funcionalidades.**
2. Interface adequada para celulares e tablets.
3. Operação rápida durante atividades presenciais.
4. Arquitetura preparada para conexão instável e evolução futura.
5. Privacidade e proteção de dados desde o início.
6. Separação entre dados de demonstração e dados reais.
7. Documentação como referência para decisões técnicas.

## 🔒 Privacidade

Aplicações de frequência podem lidar com dados pessoais.

Por esse motivo:

- dados reais não devem ser publicados;
- listas reais de participantes não devem ser enviadas ao GitHub;
- credenciais, tokens e chaves de API nunca devem ser commitados;
- exemplos públicos devem utilizar dados fictícios ou anonimizados.

A evolução do projeto deve considerar princípios aplicáveis de privacidade e proteção de dados.
